# hr-info-collection — 业务概述

> 这份文件说明项目“为什么做、给谁用、做到哪里为止”，是项目层面相对稳定的事实，不写具体需求（具体需求写在 PRD 里）。
> 初始化时由 `project-brief.yaml` 的 `background` 生成；之后由团队直接编辑，AI 不改写。
> 各 Skill 不会自动读取本文件，需要时在对话中 `@global-info/business-brief.md`；“摘要”一节会同步到工作台 `AGENTS.md` 的“项目概览”，每次会话都能读到。改了摘要，请同步改 `AGENTS.md` 的那一段。

## 摘要

HR人力信息收集系统：用户在 Web 对话中上传简历文件（PDF、照片等），由大模型（DeepSeek flash）解析内容，再与用户逐项对话校对，确认后将结构化简历信息和原始文件一并保存到本地。

## 要解决的问题

简历散落在各类文件和图片里，人工逐份录入信息慢且易错；做成后，上传即可得到按统一简历模型整理、经本人确认的结构化信息，并能回溯到原始文件。

## 目标用户

提供简历信息的用户：在对话中上传简历并校对确认解析结果。HR 人员的查看与使用方式未说明，待补充。

## 范围内

Web 对话界面；简历文件上传（PDF、照片等）；大模型解析文件内容；按预设简历模型与用户对话校对；确认后保存到本地数据库；原始文件存入项目 file 目录，并在简历记录中关联原始文件

## 范围外

只做简历信息的识别、收集、归档，其他一律不做（如简历筛选与岗位匹配、招聘流程管理、对接其他 HR 系统）

## 主要输入与输出

输入：用户上传的简历文件（PDF、照片等）和对话中的校对回复；输出：经确认的结构化简历记录（保存在本地数据库）、保存在项目 file 目录下的原始文件，以及两者的关联关系

## 成功标准

用户上传简历后，系统能够正常解析内容，将解析结果转换为预设的 HR 简历模型；经用户确认后，结构化简历记录及其原始文件关联能够成功保存。
