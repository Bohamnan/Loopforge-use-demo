## 情境（Context）

v2（HR_PR-1-CRv2）要求查看所有已保存简历的列表、详情和原始文件。系统没有账号体系；简历属于敏感个人信息（B-06）。DL 确认目标是展示能力，归档列表全局可见、不做搜索。

## 选项（Options）

### 选项 A（已选）：backend 提供只读列表、详情、原始文件下载接口，全局可见
- 优点：实现最小；原始文件由 backend 按记录关联路径读取并返回，不暴露文件目录。
- 缺点：任何能访问该服务的人都能看到全部简历。

### 选项 B（未选）：只展示本浏览器提交的简历
- 优点：暴露面小。
- 缺点：不是 HR 查看视角；换浏览器即看不到。未选原因：DL 确认全局可见。

### 选项 C（未选）：增加简单口令或账号
- 优点：有基本访问控制。
- 缺点：超出本期范围。未选原因：本期不做登录与账号能力。

## 决策（Decision）

backend 新增只读的归档列表、详情与原始文件下载接口，不做权限控制；服务只监听本机地址（127.0.0.1），以此作为本期唯一的访问边界。

## 后果（Consequences）

- 正面：满足 PRD #7；无写入能力，不影响 B-04/B-05。
- 负面（已接受风险）：同机任何人可查看全部简历；若服务改为对外监听，必须先补访问控制。
- 需跟进（LLD）：
  1. 文件下载只按记录中的关联路径读取，并校验路径位于归档目录内，不接受用户传入的路径或文件名。
  2. 下载响应使用安全的内容类型与附件文件名，不回显内部路径。
  3. 列表按保存时间倒序；数据量小（POC），是否分页由 backend 设计决定。
  4. 访问日志不记录简历字段（B-03）。
  5. 若将来对外部署：把"补访问控制"列为前置条件，写入 backend `AGENTS.md` 红线。
