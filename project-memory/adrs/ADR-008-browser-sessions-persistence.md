---
id: ADR-008
title: 历史会话以浏览器标识 Cookie 归属、服务端永久保存，只允许手动删除
status: ACCEPTED
date: 2026-11-11
---

## 情境（Context）

v2（HR_PR-1-CRv2）要求同一浏览器能看到、继续、删除历史会话；DL 确认会话一直保存、不自动清理，清理由用户手动删除。v1（ADR-003）一个浏览器只有一份草稿、7 天无活动清理、确认后删除草稿。无账号体系；F-02 要求浏览器不保存简历内容。

## 选项（Options）

### 选项 A（已选）：HttpOnly Cookie 只存随机浏览器标识；会话、草稿与对话记录存在服务端草稿库
- 优点：浏览器只持有不透明标识，F-02 不变；一个标识可关联多个会话；草稿库与正式库仍分离（ADR-003 核心不变）。
- 缺点：标识丢失（清 Cookie、换浏览器）即看不到历史；同一浏览器的所有使用者共享历史。

### 选项 B（未选）：每个会话一个令牌 Cookie
- 优点：沿用 v1 的单草稿令牌机制。
- 缺点：Cookie 数量随会话增长，无法列出历史。未选原因：不能支撑会话列表。

### 选项 C（未选）：浏览器 localStorage 保存会话列表或内容
- 优点：实现简单。
- 缺点：脚本可读；保存内容直接违反 F-02。未选原因：违反约束。

## 决策（Decision）

backend 签发长期有效的 HttpOnly 浏览器标识 Cookie（随访问续期；浏览器上限约 400 天），库内只存其 SHA-256；会话归属于该标识。会话在确认保存后保留并转为"已保存"（关联正式库的简历记录），不再自动清理；用户手动删除时：校对中会话连同草稿与临时文件删除，已保存会话只删对话记录，正式简历与原始文件不受影响。

## 后果（Consequences）

- 正面：满足 PRD #6；正式库仍只含确认后的记录（B-04）。
- 负面：草稿库数据持续增长（DL 确认本地项目不考虑存储成本）；草稿库中长期保存敏感内容，依赖受控主机磁盘加密（沿用 HLD §8 假设）。
- 需跟进（LLD）：
  1. 取消 7 天 TTL 清理调度；孤儿临时文件的处理方式由 backend 设计决定（可保留启动时扫描）。
  2. 确认保存后：草稿临时文件可在归档成功后删除（正式区已有副本）；已保存会话的只读视图从正式库读取简历内容。
  3. 幂等重复保存（ADR-004 already_saved）时，会话关联到已有的简历记录。
  4. 访问任何会话都必须校验其归属的浏览器标识，不能凭会话编号跨浏览器读取。
  5. v1 的 `draft_token` Cookie 与现有单草稿接口如何迁移或兼容，在跨 Workbench 契约审视中定。
