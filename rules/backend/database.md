# backend Workbench — 数据库/存储规范

> **加载方式**：各 SKILL **按需自主加载**（非强制）。仅当本次任务涉及库表/Schema 设计时加载。
> 与 references/{Workbench}.md 的「Workbench schema 红线」配合：本文件是团队**风格规范**，红线是 SOP **硬约束**。

---

## 1. 命名规范

- 数据库：SQLite（本地单文件）。
- 表名、字段名使用小写下划线（snake_case）。
- 具体表结构在技术设计阶段确定。

## 2. 字段类型与必备字段

- 必备/审计字段：持久化实体含 `id`、`created_at`、`updated_at`。
- SQLite 为动态类型，设计时仍须显式声明列类型并写明可空性；时间用 ISO 8601 UTC 文本。
- 简历记录与原始文件关联：原始文件存放在项目 file 目录，记录中保存关联路径；保存记录与保存文件须保持一致（B-05）。
- 具体字段在技术设计阶段确定。

## 3. 索引 / 分区 / 存储设计

- 存储访问集中在 repositories 层，日后更换数据库只改这一层。
- 索引按查询模式设计；SQLite 不使用分区。
- 设计时须覆盖：实体与关系、字段类型与可空性、审计字段、索引、保留期与清理策略。
- SQL 使用参数绑定，不拼接 SQL 字符串。
- 具体表结构在技术设计阶段确定。
